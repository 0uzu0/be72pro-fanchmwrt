BE72 Pro · UI 统一改造合并清单

目标：彻底取消简单/高级双模式，全系统只保留一套 UI。生成于实施前，作为改动与验收依据。

一、现状：双模式的完整机制（vendor 主题）

模式分流全部在主题层，共四处：

  • menu-fanchmwrt.js · getMenuCategory()：把顶级菜单分为 menu-item-basic（9 个 fwx 页面）/ menu-item-advanced（其余全部，含 LuCI 原生页）。
  • cascade.css：.menu-item-basic{display:block} / .menu-item-advanced{display:none} —— 默认就是简单模式。
  • 顶栏 ⋮ 下拉（mode-item）写 localStorage('luci-menu-category')，页面加载后 switchCategory() 按存档切换两组菜单的显示。
  • renderModeMenu()：处理 #modemenu（本主题 header 无此元素，是死代码）。

另有四处遗留问题（双模式之外，但本次一并修）：① 仓库版 menu-fanchmwrt.js 已去模式菜单，但 build.sh 从未把它拷进主题包 → 线上固件仍带模式切换；② v1.8.0 移除 luci-app-fwx-network 后，fwx_network 顶级节点失去标题 → fwx 防火墙页没有导航入口；③ 网络加速页注册在 admin/fwx/fwx_accel（API 匿名节点下）→ 无菜单入口，只能手输 URL；④ 切换到高级模式时会出现 fwx、fwx_network 两个无标题空菜单。

二、页面合并清单（顶级菜单 → 统一侧边栏）

同一功能只有一套页面实现：fwx 业务页继续用 fwx 页，LuCI 原生页继续用原生页，不存在需要删除的重复页面——重复的只是"入口分流"。合并动作 = 把两组入口合到一套侧边栏，并给三个失入口页面补入口。

四、不动的部分（兼容性红线）

  • 后端零改动：fwxd、fwx.ko、rule_manager.lua、DPI、审计、HNAT hook_toggle 联动全部不碰。
  • ubus API / dispatch API 节点（admin/fwx/*、admin/*_api/*）全部保留——只动"页面入口注册"，不动 API 注册。
  • UCI 配置（fwx、network、system、firewall…）不增不删不改名。
  • 已有用户数据（审计记录、黑白名单、规则）不受影响。
  • 构建流程：CI 只多一步文件覆盖（幂等），其余不变。

五、验收对照

  • ① 只剩一种 UI 模式 → 代码中不再有 basic/advanced、mode-item、luci-menu-category 任何一处引用（vendor CSS 中的死规则同时剥离）。
  • ② 无模式切换按钮 → ⋮ 下拉只剩「退出登录」。
  • ③ 无两套重复业务页面 → 清单二逐项核对。
  • ④ 所有功能有导航入口 → 重点验证防火墙页、网络加速页、LuCI 原生页。
  • ⑤ 高级配置可用 → MAC/应用过滤的「高级设置」标签、特征库、FullCone、EQoS、TurboAcc。
  • ⑥ 构建通过 → GitHub Actions 出镜像 + 整合包。
